# Isolated .NET SDK v0.4.0

v0.4.0 strengthens the established Isolated .NET SDK experience with historical .NET SDK compatibility, clearer terminal navigation, safer removal and recovery, richer verification, and more deterministic tests.

Published October 17, 2026. The [official v0.4.0 GitHub Release](https://github.com/infoconex/isolated-dotnet-sdk/releases/tag/v0.4.0) provides the tagged source, release notes, and checksum asset.

## Highlights

- **Historical .NET SDKs** — expanded original 1.x and early 2.x installation support, published legacy artifact/checksum handling, and precise SDK Base Path verification for hosts without modern inventory commands. Running an old SDK still depends on host OS compatibility.
- **Verify and Audit** — detailed local one-SDK health/origin reports with optional component and lifecycle information; more legible Audit release-type, status, date and update columns for isolated and read-only system SDKs.
- **Remove and recovery** — tightly verified automatic compatibility for legacy build servers, confirmed incomplete-directory cleanup, and retryable partial removals. Failed supported shutdowns continue to block deletion.
- **Interactive usability** — terminal-capability-aware screen clearing and result acknowledgement, clearer picker ownership, all prerelease SDK choices and reuse of already-loaded picker metadata.
- **Reliability and documentation** — historical and cross-platform regression tests, more efficient PowerShell test setup, release-publication failure-path checks and improved first-time-user guidance.

## Existing guarantees

Exact isolation, Microsoft archive checksum validation, stable/source identity, checksum-verified latest-stable and pinned bootstrap, read-only Audit/Verify boundaries, and PowerShell/Bash behavioral parity continue.

Experimental performance instrumentation and the unvalidated file-parallel test runner are **not** part of v0.4.0.
